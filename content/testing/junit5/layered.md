## Quick

JUnit 5 có ba phần: [[junit-platform|JUnit Platform]] (nền chạy test mà Maven, Gradle, IDE gọi vào), [[junit-jupiter|Jupiter]] (API `@Test`, `@ParameterizedTest`, extension mà bạn dùng để viết test) và [[junit-vintage|Vintage]] (chạy test JUnit 4). JUnit 6 (9/2025) giữ nguyên cách viết test của Jupiter, nâng baseline lên Java 17 và dùng chung một số phiên bản cho cả ba phần. **Mỗi method test chạy trên một instance mới của class test**, thứ tự method không được đảm bảo, và **test không được tìm thấy thì không ai báo đỏ**: CI xanh chưa chắc test đã chạy.

## Interview

**Kiến trúc**: build tool và IDE gọi JUnit Platform qua Launcher. Platform tìm các [[test-engine|test engine]] trên classpath và giao cho từng engine tìm và chạy test của nó. Jupiter là một engine, Vintage là engine cho JUnit 4 (deprecated từ JUnit 6), Cucumber và Spock cũng là engine. Thiếu engine nào thì test loại đó lặng lẽ không chạy.

**Lifecycle**: mặc định mỗi method có instance riêng (`PER_METHOD`), nên field không chia sẻ giữa các test, và `@BeforeAll` phải là `static`. `@TestInstance(PER_CLASS)` dùng một instance cho cả class: `@BeforeAll` không cần `static`, nhưng state trong field rò sang test sau.

**[[parameterized-test|Parameterized test]]**: `@ValueSource`, `@CsvSource`, `@MethodSource`, `@EnumSource` chạy một method với nhiều bộ dữ liệu, mỗi bộ hiện thành một test riêng. Trong `@CsvSource`, ô trống là `null`, còn `''` mới là chuỗi rỗng.

**[[junit-extension|Extension]]**: thay cho `@Rule` và `@RunWith` của JUnit 4. Extension cài các callback như `BeforeEachCallback`, `ParameterResolver`, đăng ký bằng `@ExtendWith`, `@RegisterExtension`, hoặc tự phát hiện qua `ServiceLoader` khi bật `junit.jupiter.extensions.autodetection.enabled=true` (tắt mặc định). `SpringExtension`, `MockitoExtension`, Testcontainers đều là extension.

**Chạy song song**: tắt mặc định. Bật `junit.jupiter.execution.parallel.enabled=true` mà chưa đặt `mode.default=concurrent` (hoặc `@Execution(CONCURRENT)`) thì test vẫn chạy tuần tự. Tài nguyên dùng chung khoá bằng `@ResourceLock`; test không chịu được chạy song song đánh dấu `@Isolated`.

**Bẫy hay gặp**: import `org.junit.Test` của JUnit 4 trong dự án chỉ có Jupiter, test không chạy mà không báo gì; tên class không khớp mẫu của Surefire (`*Test`, `*Tests`, `Test*`, `*TestCase`); `assertTimeoutPreemptively` chạy code ở thread khác nên mất `ThreadLocal` và transaction của Spring.

## Deep

- **Thứ tự method**: JUnit chạy theo thứ tự "xác định nhưng cố ý không hiển nhiên" (JUnit 6.1.3: `second()` chạy trước `first()`). Cần thứ tự thì dùng `@TestMethodOrder(OrderAnnotation.class)` với `@Order`, nhưng test phải chạy theo thứ tự thường là dấu hiệu chúng dùng chung state. Từ JUnit 6, class `@Nested` cũng theo quy tắc này, và `@TestMethodOrder` được kế thừa xuống các class `@Nested`.
- **Discovery issue** (từ JUnit 5.13): `@Test` trên method `private`, `static`, có giá trị trả về, hay inner class thiếu `@Nested` chỉ sinh một dòng `WARNING` trong log ("It will not be executed"); test không chạy, build vẫn xanh. Đặt `junit.platform.discovery.issue.severity.critical=WARNING` để những lỗi này làm hỏng build. Cách này không bắt được `org.junit.Test`, vì Jupiter không nhìn annotation của JUnit 4.
- **Chặn JUnit 4 lọt vào classpath**: Testcontainers 1.x kéo `junit:junit` 4.13.2 ở scope compile, nên IDE gợi ý import `org.junit.Test`. Không exclude được: `GenericContainer` implements `org.junit.rules.TestRule` qua class cha, thiếu JUnit 4 là `NoClassDefFoundError`. Lên Testcontainers 2.x (đã bỏ JUnit 4, đổi tên module thành `testcontainers-postgresql`...) rồi cấm `junit:junit` bằng `bannedDependencies` của Maven Enforcer; còn ở 1.x thì cấm import `org.junit.Test` bằng Checkstyle `IllegalImport` hoặc ArchUnit.
- **Build tool**: Gradle cần `useJUnitPlatform()`. JUnit 6 không còn hỗ trợ Surefire/Failsafe dưới 3.0.0. Surefire chạy unit test ở phase `test`; Failsafe chạy class `*IT`, `IT*`, `*ITCase` ở phase `integration-test` và vẫn chạy `post-integration-test` để dọn dẹp khi test fail.
- **Phiên bản**: Spring Boot 3.5 quản lý Jupiter 5.12, Spring Boot 4.0 quản lý JUnit 6.0.1. JUnit 6: Java 17 trở lên, một số phiên bản chung (ở JUnit 5, Platform đánh số 1.x còn Jupiter 5.x), chú thích null bằng JSpecify, `@CsvSource` chuyển sang FastCSV và chặt hơn (ký tự thừa sau dấu nháy đóng là lỗi), bỏ module `junit-platform-runner`. Khai báo [[bom|`junit-bom`]] để mọi artifact cùng phiên bản.
- **Assertion**: `assertAll` gom nhiều assert và báo mọi assert hỏng cùng lúc; `assertThrows` trả về exception để kiểm message; message dạng `Supplier` chỉ được tạo khi fail. `assertEquals(expected, actual)` đặt giá trị mong đợi trước, ngược với AssertJ `assertThat(actual).isEqualTo(expected)`; nhiều team dùng AssertJ vì message rõ hơn.
- **Assumption**: `assumeTrue(...)` sai thì test bị bỏ qua (aborted), không fail. Hợp khi máy dev không có Docker, nhưng dễ che một test chưa bao giờ chạy trên CI; theo dõi số test aborted.
- **Timeout**: `assertTimeout` chạy code trên thread của test và chỉ báo quá giờ sau khi code chạy xong. `@Timeout` (mặc định `SAME_THREAD`) cũng chạy trên thread của test nhưng interrupt thread khi quá giờ, nên chỉ cứu được code chịu dừng khi bị interrupt. `assertTimeoutPreemptively` chạy code ở thread `junit-timeout-thread-N` (đo: `ThreadLocal` đặt trong `@BeforeEach` đọc ra `null`), nên phần đó nằm ngoài transaction của test Spring và không được rollback. Đặt `junit.jupiter.execution.timeout.default` để test treo không làm treo cả CI.
- **`@Nested`**: nhóm test theo ngữ cảnh ("khi giỏ hàng rỗng"); `@BeforeEach` của class ngoài chạy trước của class trong. Từ Java 16, inner class được có member `static`, nên `@BeforeAll` static trong `@Nested` chạy được.
- **Extension giữ state ở đâu**: một instance extension có thể phục vụ nhiều test, kể cả chạy song song. Lưu state trong `ExtensionContext.Store` (theo namespace, tự dọn khi context kết thúc) thay vì field. Thứ tự: extension đăng ký trước chạy callback "before" trước và callback "after" sau.
- **Cách sinh test khác**: `@TestFactory` sinh dynamic test lúc chạy, nhưng `@BeforeEach` chỉ chạy một lần cho cả factory chứ không cho từng dynamic test. `@ParameterizedClass` (5.13) chạy cả class với nhiều bộ tham số. Còn có `@RepeatedTest`, `@TempDir`.
- **Chuyển từ JUnit 4**: `@Before`/`@After` thành `@BeforeEach`/`@AfterEach`, `@BeforeClass` thành `@BeforeAll`, `@Ignore` thành `@Disabled`, `@Category` thành `@Tag`, `@Test(expected = ...)` thành `assertThrows`, `@RunWith` và `@Rule` thành extension. OpenRewrite có recipe làm phần lớn việc này (bài Refactoring & tech debt).
- **`@MethodSource`**: method cung cấp dữ liệu phải `static`, trừ khi class dùng `@TestInstance(PER_CLASS)`.
- **Tag**: `@Tag("slow")` rồi lọc bằng `groups`/`excludedGroups` của Surefire hoặc `includeTags` của Gradle, để tách bộ chạy mỗi commit với bộ chạy đêm.
- **Song song trong JVM hay nhiều JVM**: song song của JUnit dùng nhiều thread trong một JVM, mặc định số thread bằng số core. Mặc định vẫn là ForkJoinPool; JUnit 6.1 thêm lựa chọn executor dựa trên thread pool thường (`junit.jupiter.execution.parallel.config.executor-service=WORKER_THREAD_POOL`). `forkCount` của Surefire chạy nhiều JVM: cô lập state `static` nhưng tốn bộ nhớ, và cache `ApplicationContext` của Spring không dùng chung giữa các JVM. State `static` dùng chung là nguồn [[flaky-test|test chập chờn]] hay gặp nhất khi bật song song (bài Kiểm thử code đồng thời).
